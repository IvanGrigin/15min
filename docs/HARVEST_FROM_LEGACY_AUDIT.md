# Что забрать из ветки `codex/russian-text-migration`

Ветка другого разработчика решала **ту же задачу** — падежи в текстах —
но в старой архитектуре: правкой 33 Python-генераторов. Генераторы
заархивированы (`docs/ARCHIVED_LEGACY.md`), поэтому саму ветку мерджить
некуда. Здесь — то, что из неё стоит забрать при переносе задач в JSON.

Ветка: `origin/codex/russian-text-migration`, два коммита от 24.07.2026,
49 файлов, +846/−120. В `main` не вливалась и вливаться не должна.

## Чем их подход отличался

Падежи там не решались, а **обходились**. Пример — та самая задача про погоню,
с которой начался весь разбор:

```
было:  {a} идёт впереди {b} … Через сколько минут {b} догонит {a}?
стало: {a} идёт впереди, а {b} догоняет идущего впереди …
       Через сколько минут они встретятся?
```

Имя выведено из всех косвенных позиций. В комментарии к правке это сказано
прямо: «вопрос ссылается на роли, поэтому эвристическое склонение составного
имени не нужно». В задаче про муравья персонаж вообще заменён словом
«Муравей», а имя осталось только в служебном `role_mapping`.

Словарь форм — `reviewed_character_forms.json`, **11 персонажей из 150**,
по 4 падежа (без творительного и предложного, без множественного числа).
Политика для остальных: если имени нет в списке, персонаж просто не выбирается
на роль, требующую склонения, — то есть пул персонажей сужается.

Наш путь противоположен: 268 персонажей × 6 падежей, склонение как первоклассная
операция шаблона, обходить формулировку не нужно.

## Перекрёстная проверка форм: сошлось полностью

Их 11 записей сверены с нашим реестром: **11 совпало, 0 расхождений**, включая
трудные составные имена — «Гектора Барбоссы», «Джека Воробья», «Ивану Царевичу»,
«Кузю». Две независимые ручные выкладки дали один результат — это хорошая
проверка нашего реестра, и её стоит зачесть.

## Что забрать: список дефектов

Главная ценность ветки — не код, а **найденные дефекты**. У них был внешний
аудит 1000 задач с реестром замечаний. Когда соответствующая исходная задача
будет переноситься в JSON, эти находки надо учесть заранее, иначе баг переедет
в новый шаблон вместе с задачей.

### Математические ошибки в исходных формулировках и решениях

| Код | Тема | Что было не так |
|---|---|---|
| MATH-001 | движение, знакопеременное смещение | ответ умножался на 60 — минуты ошибочно переводились в секунды |
| MATH-002 | часовые пояса, время в пути | брался остаток по модулю 24 часа, терялся день прибытия |
| MATH-003 | чётность, сумма по признаку | текст и решение использовали **разные** предикаты |
| MATH-004 | муха между пешеходами | целочисленное деление вместо точной дроби — ответ обрезался |
| MATH-005 | цифры, интервал с исключениями | границы интервала обходились не по обоим условиям |
| MAT-001 | встречные поезда | длины поездов принудительно равнялись половинам общей длины |
| MAT-002 | куб, глубина воды | путались литры и площадь пола в м² |
| MAT-003/4/8 | кубики | неверный подсчёт рёберных кубиков и видимых граней |
| MAT-006 | расходящиеся часы | первое совпадение искалось без сравнения по модулю 1440 |

### Смысловые и языковые дефекты

| Код | Тема | Что было не так |
|---|---|---|
| — | трамваи по кругу (задачи 307, 325) | **время прохождения круга названо длиной маршрута** |
| — | доли | «одной 4-й» вместо «одной четверти» |
| — | арбуз, усушка | «воды стало 98%» — неоднозначно, кто стал 98% |
| — | клетчатые фигуры | размеры без единицы «клетка» |
| — | расходящиеся часы | «первые/вторые» часы — непонятно, чьи |
| — | разделение счёта | «первая доля» без указания плательщика |
| — | турниры | ограничить модель полными турами, иначе вопрос неоднозначен |

Задачу про трамваи я уже поставил в очередь батча `calendar_and_weekdays`
(307, 325) — замечание про «время круга ≠ длина маршрута» надо учесть
при написании условия.

### Признано неразрешимым в старой архитектуре

- `LOGIC-003`, `LOGIC-004` — доказательные шаблоны выключены: read-only
  формулировка не даёт основания выдавать полный доказательный ответ.
  У нас это причина отклонения `structured_answer`.
- `LOG-008` — ключ ответа допускает только одно значение, а нужно множество
  допустимых. У нас та же граница: `answer_type` не поддерживает «любой из».
- `LOG-009` — нужна метрика нетривиальности периода для рекуррентных
  последовательностей.

## Что делать с веткой

1. **Не мерджить.** Она патчит код, которого на `main` больше нет.
2. **Не удалять.** Пусть лежит рядом с `archive/legacy-python-generators`
   как след аудита; на неё ссылается этот файл.
3. **Предупредить автора**, что направление сменилось, — иначе работа
   продолжится по архивной ветке. Ссылка для него: `docs/ARCHIVED_LEGACY.md`
   и `docs/AGENT_TASK_TO_TEMPLATE_PROMPT.md`.
4. **Спросить исходный реестр аудита** — `1000_math_problems_issue_register.csv`
   передавался вне репозитория. В нём остальные коды `RU-*`, `GRAM-*`,
   `QUALITY-*`, которые здесь пересказаны только группами. Для переноса
   полезнее полный список, чем сводка.
