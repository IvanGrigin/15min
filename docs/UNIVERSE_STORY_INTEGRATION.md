# Сюжеты вселенных в Template Studio

Сюжетный слой детерминирован: Python выбирает и проверяет данные, но не
сочиняет условие. Текст, слоты и математическая модель остаются в JSON-шаблоне.

## Режимы

- `universe` — одна вселенная на всю задачу; персонажи, локации, предметы,
  валюта и жители берутся только из неё.
- `common` — только `common_names.json` и нейтральные слова.
- `neutral` — без имён: животные, транспорт или математические объекты.
- `abstract` — без искусственного сюжета.

Профиль `universe` обязан содержать `same_universe: true`. Runtime сохраняет
скрытый `story_context` и проверяет `character_id`, принадлежность локаций и
источник каждой леммы (`items`, `valuables`, `currency` или `folk`).

## Совместимость

Правила лежат в `data/language/situation_compatibility.json`, а проверенные
размерные профили — в `data/language/character_compatibility.json`. Персонаж
без профильной записи не допускается в размерно-чувствительную сцену.

Например, Тигрица не может появиться на узкой палочке, но может идти по мосту
или тропе; муравей допустим на узкой опоре. Способ движения всегда берётся из
явного поля `motion`, а не из имени персонажа.

## Добавление данных

Новая вселенная добавляется в `data/entities/universes.json`; новые персонажи
— в один из файлов `data/entities/characters/`; существительные — в
`data/language/nouns/russian_nouns.json`. У персонажа обязательны явный род,
шесть форм, `motion` и `age_class`. Не определяйте род, вселенную или размер
по написанию имени.

## Проверка

```bash
python scripts/export_story_review.py --output story_review.json --variants 3
python -m unittest tests.test_story_contexts -v
```

Экспорт предназначен для ревью и содержит скрытые `story_context`, выбранные
леммы, идентификаторы персонажей и ответ. Сайт ученику эти поля не показывает.
