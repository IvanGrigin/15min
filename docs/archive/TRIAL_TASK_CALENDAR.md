# Пробное задание: батч «Календарь и дни недели»

Этот файл — задание для нового агента и одновременно проверка того, достаточно ли
правил в репозитории, чтобы работать без дополнительных объяснений. Если агенту
пришлось что-то додумывать — виноват не агент, а документация, и её надо править.

---

## Задание

Ты работаешь в репозитории генератора математических пятиминуток.

**Сначала прочитай `AGENTS.md` целиком.** Дальше действуй по правилам оттуда
и по документам, на которые он ссылается. Ничего не выдумывай сверх них:
если правило кажется неполным — так и напиши в отчёте, а не изобретай своё.

Перенеси в JSON-шаблоны батч из модуля `calendar_and_weekdays`:

| Задачи корпуса | Сюжет |
|---|---|
| 36, 833, 1042 | трое друзей ходят в одно место с разной периодичностью |
| 307, 325 | трамваи по кругу, интервал движения |
| 305, 323 | школьный день: уроки, большая и короткие перемены |
| 198, 216, 1268 | занятия два раза в неделю в фиксированные дни |

Тексты задач ищи в корпусе — где именно, сказано в `AGENTS.md`.

Задача, которую нельзя выразить формулой, **отклоняется** — это нормальный
результат, а не неудача. Причины отклонения перечислены в правилах.

## Что должно получиться

1. Шаблоны в `data/template_studio/library/`, прошедшие публикацию.
2. Тест с независимым решателем.
3. Запись в журнале переноса.
4. Полный прогон тестов — зелёный.
5. Отчёт по форме из раздела «Форма отчёта после батча».

## Как оформить работу

Работай в отдельной ветке и **коммить по ходу дела, но не пушь**:

```bash
git switch -c trial/calendar-batch
```

Коммиты атомарные, по смыслу: отдельно данные, отдельно шаблоны, отдельно
тесты, отдельно журнал. Сообщения честные — если попытка не удалась и ты
её переделал, так и напиши в сообщении следующего коммита.

**Неудачные попытки не откатывай молча.** История коммитов — часть результата:
по ней видно, где правила подсказали верный путь, а где пришлось гадать.

## Чего делать не нужно

- Пушить: ветку смотрит человек локально.
- Трогать корпус исходных задач.
- Заводить новые Python-модули под конкретную задачу.

## Как это будет проверяться

Проверяющий агент пройдётся по списку. Он открыт заранее — не чтобы подсказать
ответы, а чтобы правила и их проверка совпадали.

**Соблюдение железных правил**

- [ ] в `problemgen/` не появилось ни одного нового файла;
- [ ] ни одной f-строки с текстом условия в Python;
- [ ] падежные формы не выдуманы в коде, а взяты из реестров;
- [ ] валидация не ослаблена ради прохождения шаблона.

**Качество шаблонов**

- [ ] десять примеров каждого шаблона читаются как нормальный русский:
      падежи, род глагола, согласование числительных, предлоги;

- [ ] ответ проверен независимым решателем, а не пересказом той же формулы;
- [ ] числа осмысленные: задача остаётся устной пятиминуткой;
- [ ] доля годных наборов не ниже порога, указанного в правилах.

**Работа с известными дефектами**

      не подсказано в этом задании.

**Дисциплина**

- [ ] отклонённые задачи записаны с причиной из списка;
- [ ] журнал обновлён;
- [ ] прогон тестов зелёный;

**Обратная связь по документации**

- [ ] что в правилах оказалось непонятным или недостающим — это ценнее,
      чем безупречно выполненный батч.
