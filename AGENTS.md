# AGENTS.md

Обязательные правила для любого агента, работающего в этом репозитории.
Читается целиком перед первым изменением.

## Главный принцип

**Python решает задачу. JSON её формулирует.**

Одна задача — одна JSON-запись в `data/template_studio/library/`. Из неё
генератор без нейросети собирает бесконечно много корректных по-русски
вариантов с автоматически посчитанным ответом.

Генерация детерминированная и проверяемая: LLM не участвует в момент выдачи
задачи ученику. Модель может помогать человеку разбирать исходную задачу,
но её результат обязан пройти валидацию без неё.

## Что запрещено

1. **Писать Python-генераторы задач.** Никаких f-строк с текстом условия,
   никаких новых модулей вида `*_templates.py`, никаких веток «если модуль X».
2. **Хранить в коде** текст условия, имена персонажей, названия предметов
   или их словоформы. Всё это — данные.
3. **Восстанавливать архивный стек** или копировать из него код.
   См. `Docs/ARCHIVED_LEGACY.md`: направление закрыто, а не приостановлено.
4. **Ослаблять валидацию**, чтобы шаблон прошёл. Не проходит — виноват шаблон.
5. **Автоматически склонять слова в рантайме.** Все формы задаются явно
   в данных. Правила склонения (`scripts/declension_rules.py`) — инструмент
   подготовки данных, а не часть движка.

## Что разрешено и ожидаемо

- Добавлять JSON: шаблоны задач, персонажей, локации, существительные.
- Писать одноразовые исследовательские скрипты в `/tmp` (в репозиторий не кладём).
- Писать **тест с независимым решателем** — единственное место, где Python
  имеет право знать математику задачи. Решатель обязан решать задачу заново
  по её условию, а не повторять формулу шаблона.
- Расширять движок, если не хватает **общей** возможности (новый падежный слот,
  новый тип параметра). Не «логика конкретной задачи», а операция для всех.

## Порядок работы над задачей

Полный алгоритм из 13 шагов — `Docs/AGENT_TASK_TO_TEMPLATE_PROMPT.md`.
Коротко: разобрать математику руками → проверить осмысленность по всему
диапазону → измерить долю годных наборов (порог 5 %) → добрать недостающие
данные → написать текст со слотами → constraints по чек-листу → прочитать
десять примеров глазами → тест-решатель → публикация → журнал.

Батч — 10–15 задач. После батча: полный прогон тестов, обновление журнала,
отчёт. В отчёте обязательна строка «изменения в Python» — если там что-то,
кроме «нет», это должна быть общая возможность движка, а не логика задачи.

## Пополнение данных

```bash
python3 scripts/data_agent_loop.py --queue data/language/queue/nouns.json --rules-only
```

```bash
python3 scripts/data_review.py
```

Правила готовят двенадцать форм, механические проверки (`tests/test_noun_dictionary_integrity.py`)
отсеивают невозможное, человек вычитывает компактную таблицу. Замеры и границы
применимости — `Docs/DATA_PIPELINE.md`.

Локальная языковая модель в этой роли **измерена и отклонена**: она путает
творительный с винительным и предложный с дательным. Не возвращайте её без
нового замера.

## Отклонить задачу — нормальный результат

Причины: `non_parametric`, `search_answer`, `structured_answer`, `duplicate`,
`corrupt_source`, `needs_new_slot`. Записывается в журнал с номером и причиной.
Плохой результат — не отклонённая задача, а шаблон с кривым русским
или неверным ответом.
