# Конвейер пополнения данных

Как массово добавлять существительные, персонажей, локации и предметы, не тратя
человека на каждую из двенадцати форм. Решения ниже приняты не по интуиции,
а по измерениям на живом материале — цифры приведены.

## Что измеряли

Пилот на реальных задачах корпуса, локальная модель `qwen3:8b` через Ollama.

### Локальная модель как автор шаблонов задач — не работает

| | Прогон 1 | Прогон 2 (+автопочинка) | Прогон 3 (+словарь) |
|---|---|---|---|
| Прошли валидатор | 1 / 10 | 2 / 10 | 4 / 10 |
| **Годны к публикации** | **0 / 10** | **0 / 10** | **0 / 10** |

Ноль трижды подряд. Причём валидатор проходят шаблоны, которые нельзя показывать:

- `work_five_fishermen`: формула свернулась в `m / (n * (m/n))` — тождественная
  единица. Ответ «1 день» при любых числах.
- `money_group_exchange`: в `math_notes` справедливый делёж выписан верно,
  а в `answer_expression` стоит `n2 * exchange_rate` — комиссия и делёж потеряны.
- `work_approach_line`: в заметках сказано «расстояние удаления `|v1-v2|·t`»,
  в формуле — сближение `n0 − (v1+v2)·t`. Противоречие внутри одной записи.

Вывод: рассуждение и формула у модели расходятся, а валидатор этого не видит —
он проверяет самосогласованность, а не правильность.

### Локальная модель как источник словоформ — тоже не работает

29 слов, сверка с независимо посчитанными правилами: совпало 24 %, разошлось 76 %.
**В расхождениях права оказалась не модель, а правила.** Ошибки не на исключениях,
а на регулярном:

| Слово | Модель | Правильно |
|---|---|---|
| парта, творительный | партой → **парту** | партой |
| коробка, предложный мн. | коробках → **коробкам** | коробках |
| покупатель, предложный | **«у покупателя»** | покупателе |
| продавец, именительный | **продавца** | продавец |

Модель систематически сдвигает падеж по позиции и иногда вписывает предлог
внутрь формы. Для морфологии она хуже простых правил.

### Правила склонения — рабочая основа

Сверка `scripts/declension_rules.py` с 229 выверенными вручную словами:

- там, где правила уверены (72 % слов) — **точность 80 %**;
- остальные 28 % правила сами помечают как рискованные.

80 % мало для слепого приёма, но много для заготовки: человек читает готовую
таблицу вместо того, чтобы писать двенадцать форм руками.

## Рабочая схема

```
очередь слов -> правила склонения -> механические проверки -> таблица человеку -> словарь
```

```bash
python3 scripts/data_agent_loop.py --queue data/language/queue/nouns.json --rules-only
```

```bash
python3 scripts/data_review.py
```

Механические проверки отсеивают невозможное без человека — это правила русского
языка без исключений, они же живут постоянными тестами
в `tests/test_noun_dictionary_integrity.py`:

- винительный мн. = родительный мн. у одушевлённых, = именительный мн. у неодушевлённых;
- после к, г, х, ж, ш, ч, щ пишется -и, а не -ы;
- ни одной пустой формы, `count_forms` ровно из трёх элементов.

Проверка человеком — одна строка на слово: начальная форма, родительный,
творительный, предложный, именительный мн., родительный мн. Ошибки видно сразу.

### Результат на 29 словах

19 заготовок принято без правок, 10 помечено на проверку. При чтении таблицы
человек нашёл 4 ошибки (86 % верных): `стул` → нерегулярное «стулья/стульев»,
`окно` → «окон», а не «окен», `продавец` и `огурец` → творительный на -цом,
а не -цем (ударное окончание). Все 29 слов в словаре, 330 тестов зелёные.

## Чего эти правила не знают

Помечается как «на проверку» автоматически:

- беглая гласная (венок → венка, но поток → потока);
- выбор -ек/-ок в родительном мн. (ложек, но коробок);
- чередование в основе (метла → мётел, звезда → звёзд).

Не помечается и требует внимания человека:

- нерегулярное множественное на -ья (стул → стулья, лист → листья);
- ударное окончание творительного у слов на -ец (огурцом, а не огурцем);
- супплетивные формы (человек → люди, год → лет) — задаются через `count_forms`.

## Побочный результат: правила нашли ошибки в старых данных

Сверка правил с уже существующим словарём выявила 15 дефектов, которые никто
не замечал: у одиннадцати слов (`балл`, `грамм`, `метр`, `литр`, `час`, `рубль`,
`месяц`, `раз`, `сантиметр`, `дециметр`, `килограмм`) именительный множественного
был скопирован из родительного единственного («грамма» вместо «граммы»);
у `человек` три падежа множественного были забиты счётной формой вместо
«люди / людей»; у `голова` и `нога` винительный множественного не соответствовал
неодушевлённости. Всё исправлено, класс ошибок закрыт тестом.

## Роль локальной модели

По результатам измерений — никакой. В обеих ролях она проигрывает либо человеку,
либо детерминированным правилам, а разбор её брака стоит дороже, чем сделать
сразу правильно. Код конвейера (`scripts/agent_loop.py`, режим с Ollama
в `data_agent_loop.py`) сохранён: если появится модель существенно сильнее,
замер повторяется одной командой и решение можно пересмотреть на цифрах.
