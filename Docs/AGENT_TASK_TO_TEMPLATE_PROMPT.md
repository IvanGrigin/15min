# Промпт агенту: перенос задач из корпуса в JSON-шаблоны

Этот файл — полная инструкция для агента, который переводит задачи из read-only корпуса
(`Docs/all_tasks_all_files.md` и тематические `Docs/NN_*.md`) в декларативные шаблоны
Template Studio. Читается целиком перед началом работы.

Обязательный контекст: `Docs/TEMPLATE_ARCHITECTURE_DECISION.md` — почему выбран
именно такой формат и как устроен вертикальный срез.

---

## 0. Цель одной фразой

Превратить каждую пригодную задачу корпуса в **одну JSON-запись**, из которой
генератор без нейросети и без нового Python-кода собирает бесконечно много
корректных по-русски вариантов этой задачи с автоматически посчитанным ответом.

---

## 1. Железные правила

**Запрещено:**

1. Писать Python-генераторы задач. Никаких новых файлов в `problemgen/generation/`,
   никаких новых веток в `worksheet_site.generate_combined_worksheet_by_modules`,
   никаких f-строк с текстом задачи.
2. Хранить текст условия, имена персонажей, названия предметов или их формы
   в Python-коде. Всё это — данные.
3. Править 33 старых модуля в `problemgen/generation/*_templates.py`. Они живут
   своей жизнью и будут выключаться по мере переноса — но не тобой и не сейчас.
4. Использовать LLM в момент генерации задачи. Модель участвует только на этапе
   разбора исходного текста при подготовке JSON; результат обязан проходить
   валидацию без неё.
5. Ослаблять валидацию, чтобы шаблон «прошёл». Если шаблон не проходит — виноват
   шаблон, а не проверка.

**Разрешено и ожидаемо:**

- Добавлять JSON-файлы: шаблоны, персонажей, существительные.
- Писать **одноразовые исследовательские скрипты** (в `/tmp`, не в репозиторий),
  чтобы подобрать диапазоны параметров и измерить долю годных наборов.
- Писать **тест с независимым решателем** — Python, который решает задачу
  по её условию с нуля и сверяет результат с ответом шаблона. Это единственное
  место, где Python имеет право знать математику задачи.

Формула для памяти: **Python решает задачу, JSON её формулирует.**

## 3. Единица работы

Одна исходная задача → одно из двух:

- **шаблон** — JSON-файл в библиотеке, прошедший валидацию и активированный;
- **отклонение** — запись в `Docs/MIGRATION_LEDGER.md` с номером задачи, темой
  и причиной из списка в разделе 12.

Промежуточных состояний нет. Незаконченный шаблон в библиотеке не оставляют.

## 4. Пошаговый алгоритм

1. **Выбрать задачу.** Порядок обхода — раздел 13.
2. **Понять математику.** Выписать на бумаге: что дано, что ищется, какие
   соотношения связывают величины. Не начинать JSON, пока решение не выписано.
3. **Обобщить.** Какие числа в задаче свободны, а какие вычисляются? Свободные
   станут `parameter_schema`, вычисляемые — `derived_values`.
4. **Проверить осмысленность.** Прогнать формулы по всему диапазону: не возникает
   ли отрицательного времени, нулевой скорости, нецелого числа людей, физически
   абсурдных значений (см. раздел 9). Обычно на этом шаге выясняется, что задача
   жёстче, чем кажется.
5. **Измерить долю годных наборов** одноразовым скриптом в `/tmp`. Если меньше 5 % —
   переparametrизовать (раздел 8), а не увеличивать лимит попыток.
6. **Собрать персонажей и предметы.** Каких имён и слов не хватает в реестрах?
   Добавить их (разделы 6 и 7) — с полными формами, вручную, без автосклонения.
7. **Написать текст шаблона** со слотами (раздел 5.3). Каждое упоминание персонажа —
   слот с падежом. Каждый глагол прошедшего времени рядом с персонажем — слот `:g,`.
   Каждое число рядом с существительным — слот `:count,`.
8. **Описать ответ**: `answer_expression`, `answer_type`, `answer_rendering`.
9. **Записать `constraints`** по чек-листу раздела 9.
10. **Прогнать** `--preview --only <id>` и **прочитать 10 примеров глазами**.
    Проверить по чек-листу раздела 10. Это не формальность: валидатор ловит
    структуру, но не ловит смысл.
11. **Написать тест** с независимым решателем (раздел 11).
12. **Активировать** и убедиться, что все 10 проверок `OK`, ошибок 0,
    доля удачных ≥ 5 %.
13. **Записать в журнал** `Docs/MIGRATION_LEDGER.md`.

## 5. Спецификация шаблона

### 5.1 Файл

`data/template_studio/library/<template_id>.json`. Имя файла обязано совпадать
с `template_id`. `template_id` — строчные латинские буквы, цифры и `_`, 3–81 символ.

### 5.2 Поля

| Поле | Обяз. | Что это |
|------|-------|---------|
| `schema_version` | да | всегда `1` |
| `template_id` | да | совпадает с именем файла |
| `module_id` | да | одно из 31 значения в `data/templates/problem_sets/catalog.json` |
| `language` | да | `"ru"` |
| `solver_strategy` | да | `"formula"` (единственное, что можно активировать) |
| `candidate_template_text` | да | текст условия со слотами; заканчивается `.`, `?` или `!` |
| `parameter_schema` | да | свободные параметры (см. 5.4) |
| `derived_values` | да | вычисляемые величины: имя → выражение |
| `constraints` | да | список строк-предикатов |
| `answer_expression` | да | выражение ответа |
| `answer_type` | да | `integer`, `number`, `fraction`, `text`, `list`, `multi_part`, … |
| `answer_rendering` | да | как печатать ответ с единицами (см. 5.6) |
| `grammar_metadata` | нет | роли персонажей, заметки для людей |
| `source_metadata` | да | `problem_number` и `filename` исходной задачи |
| `math_notes` | нет | разбор математики для следующего агента — **пиши его** |
| `notes` | нет | короткая пометка об уровне сложности |

### 5.3 Слоты в тексте

| Слот | Что даёт | Требование к параметру |
|------|----------|------------------------|
| `{n}` | число как есть; дробное печатается через запятую | любой |
| `{hero:nom}` `{:gen}` `{:dat}` `{:acc}` `{:ins}` `{:pre}` | падеж полного имени | `character` или `noun` |
| `{apple:nom_pl}` … `{:pre_pl}` | формы мн. ч. | `noun` |
| `{apple:count,n}` | «5 яблок», «2 яблока», «2,5 часа» | ключ — `noun`, аргумент — число |
| `{apple:agree,n}` | согласованная форма без числа | то же |
| `{hero:g,купил\|купила}` | форма по роду; можно три формы для среднего | `character` или `noun` |
| `{place:loc}` | **где**: предлог + предложный падеж — «в Хогвартсе», «на пляже» | `location` |
| `{place:dir}` | **куда**: тот же предлог + винительный — «в Хогвартс», «на пляж» | `location` |
| `{hero:with}` | «с»/«со» + творительный — «со Свеном», но «с Нюшей» | любой с падежами |

Три последних слота существуют потому, что выбор предлога нельзя доверить автору
шаблона: слово выбирается случайно, а предлог зависит от его формы. «в» или «на»
лежит в данных локации; «с» или «со» вычисляется по стечению согласных.
Путать `loc` и `dir` нельзя: «отправился в Хижине чудес» — сломанный текст.

Порядок аргументов в `count`/`agree`: **сначала существительное, потом число** —
`{apple:count,n}`, а не `{n:count,apple}`. Частая ошибка.

Заглавную букву в начале предложения ставит движок — не подгоняй имена руками.

### 5.4 Типы параметров

| Тип | Поля | Примечание |
|-----|------|-----------|
| `integer`, `positive_integer`, `nonnegative_integer` | `min`, `max` | |
| `decimal`, `fraction` | `min`, `max` | |
| `choice` | `allowed_values` | лучший способ задать «красивые» значения |
| `character` | `universe`, `gender`, `universe_binds` | по умолчанию все персонажи шаблона — из одной вселенной и не повторяются |
| `noun` | `lemma`, `lemmas`, `lemmas_by_universe` или `from_universe_items: true` | последнее берёт предмет из списка мира в `data/entities/universes.json` — не надо повторять перечень в каждом шаблоне |
| `location` | `universe`, `preposition`, `universe_binds` | локация того же мира, что и персонажи; `preposition: "на"` сузит выбор |
| `boolean`, `word`, `letter`, `name`, `integer_list`, `word_list` | `allowed_values` | |

Пример привязки предметов к вселенной:

```json
"item": {
  "type": "noun",
  "lemmas_by_universe": {
    "Простоквашино": ["корова", "конфета", "книга"],
    "_default": ["яблоко", "книга"]
  }
}
```

### 5.5 Выражения

Безопасный вычислитель (`problemgen/template_studio/safe_expressions.py`) знает:

- арифметику `+ - * / // % **`;
- сравнения `< <= > >= == !=`, логику `and or not`, тернарник `a if cond else b`;
- функции `abs min max sum gcd lcm factorial`;
- списки и кортежи.

Не знает: атрибутов, импортов, лямбд, циклов, срезов, произвольных вызовов.

`derived_values` разрешаются в топологическом порядке — можно ссылаться на другие
derived-значения, циклы запрещены.

**Целочисленность.** `//` молча округляет вниз. Если результат обязан быть целым —
пиши `//` **и** ставь constraint на делимость:

```json
"derived_values": { "walk_m": "v1 * walk_min * 50 // 3" },
"constraints":    [ "(v1 * walk_min) % 3 == 0" ]
```

### 5.6 Ответ

```json
"answer_expression": "[foot_km, ride_min]",
"answer_type": "multi_part",
"answer_rendering": {
  "type": "multi_part",
  "parts": [
    { "label": "1)", "value": "foot_km", "unit": "километр" },
    { "label": "2)", "value": "ride_min", "unit": "минута" }
  ]
}
```

`value` — имя параметра или derived-значения; `unit` — лемма из словаря
существительных. Целое число согласуется по правилу счёта («10 минут»),
дробное — родительным падежом ед. ч. («11,5 километра»).

Если единица измерения сама выбирается случайно — например, параметр типа
`noun` с несколькими `lemmas` («олимпиада» или «викторина») — используйте
`unit_param` вместо `unit`: это имя параметра, чьё значение уже является
существительным, и ответ согласуется именно с тем словом, что попало в текст
задачи, а не с захардкоженной леммой.

```json
{ "label": "", "value": "total_per_hour", "unit_param": "activity" }
```

Задача с пунктами «а) … б) …» переносится как `multi_part`; в тексте пункты
нумеруются цифрами `1)`, `2)` — буквенные маркеры движок сделает заглавными.

## 6. Персонажи

Файл `data/entities/characters/approved_characters.json`, запись:

```json
{
  "character_id": "prostokvashino_matroskin",
  "universe": "Простоквашино",
  "gender": "m", "animate": true,
  "indeclinable": false, "lowercase_start": true,
  "cases": {
    "nom": "кот Матроскин", "gen": "кота Матроскина", "dat": "коту Матроскину",
    "acc": "кота Матроскина", "ins": "котом Матроскиным", "pre": "коте Матроскине"
  }
}
```

Правила:

1. **Имя пишется целиком, вместе с приложением.** «кота Матроскина», а не «Матроскина».
2. **Род задаётся явно.** Никаких догадок по окончанию: «галчонок Хватайка» — мужской,
   «Чебурашка», «Незнайка», «Йода», «Симба» — мужские, хотя кончаются на -а/-я.
3. **`indeclinable: true`** для Фродо, Гимли, Йоды, Динь-Динь, Иа-Иа — тогда все шесть
   форм совпадают, и загрузчик это проверяет.
4. **`lowercase_start: true`**, если имя начинается со строчной буквы. Заглавную
   в начале предложения поставит движок.
5. **Канон против расширения.** Реестр персонажей состоит из трёх файлов:

   | Файл | Что там | Сверяется с markdown |
   |------|---------|----------------------|
   | `approved_characters.json` | канон: 25 вселенных × 6 = 150 персонажей | да, тестом `test_registry_names_match_markdown_source` |
   | `extended_characters.json` | миры сверх канона: Гравити Фолз, мифы Греции, легенды, сказки народов мира, Disney сверх списка | нет, по построению |
   | `common_names.json` | обычные имена детей (Вася, Петя, Надя) | нет |

   В канонический файл нельзя добавить персонажа, которого нет в
   `Docs/approved_dimensions_150_characters.md`. Новый мир — только в расширенный файл.
6. Вселенная считается готовой, когда в ней **все 6 персонажей** и есть запись
   в `data/entities/universes.json` (локации и предметы). Тесты
   `test_every_described_universe_has_characters` и
   `test_every_character_universe_is_described` следят за обеими сторонами связи.
7. **Несклоняемость проверяется данными.** Если все шесть форм совпали, а флаг
   `indeclinable` не выставлен — тест упадёт. Это защита от «забыл просклонять».

Сомнительные формы (Хватайки/Хватайку, Барбоссы/Барбоссу, Мурки/Мурку) проверяй по
словарю, а не по слуху. Ошибка в реестре размножится по всем шаблонам.

## 7. Существительные

Файл `data/language/nouns/russian_nouns.json`, ключ — начальная форма:

```json
"километр": {
  "gender": "m", "animate": false, "legs": null,
  "tags": ["unit_length"],
  "forms": {
    "nom": "километр", "gen": "километра", "dat": "километру", "acc": "километр",
    "ins": "километром", "pre": "километре",
    "nom_pl": "километры", "gen_pl": "километров", "dat_pl": "километрам",
    "acc_pl": "километры", "ins_pl": "километрами", "pre_pl": "километрах"
  }
}
```

Все 12 форм пишутся руками — именно поэтому работают «год → лет» и «человек → людей».
Если формы счёта нестандартные, добавь `count_forms: [1, 2-4, 5+]`
(«два пирожных», а не «два пирожного»).

**Вещественные существительные** помечай `"countable": false` — молоко, мёд, каша,
лапша, масло. Такое слово нельзя ставить в счётный слот: «5 мёдов» — сломанный текст,
а не редкая форма. Загрузчик вселенных запрещает класть их в `items`.

Орфографическая ловушка при массовом добавлении: после **к, г, х, ж, ш, ч, щ**
пишется **-и**, а не **-ы** — «посылки», а не «посылкы». В родительном единственного
и в именительном/винительном множественного это самая частая механическая ошибка.

## 7а. Локации и предметы вселенной

Файл `data/entities/universes.json`. Одна запись на вселенную: группа миров,
локации с полной падежной парадигмой и список предметов.

```json
{
  "universe": "Гарри Поттер",
  "group": "modern_classics",
  "locations": [
    { "location_id": "hp_hogwarts", "preposition": "в", "gender": "m",
      "cases": { "nom": "Хогвартс", "gen": "Хогвартса", "dat": "Хогвартсу",
                 "acc": "Хогвартс", "ins": "Хогвартсом", "pre": "Хогвартсе" } }
  ],
  "items": ["палочка", "метла", "зелье", "свиток", "книга"]
}
```

`preposition` обязателен и лежит в данных: из формы слова он не выводится
(«в Хогвартсе», но «на пляже»). `items` — только леммы, уже существующие
в словаре существительных и только исчисляемые.

## 8. Математика: как параметризовать

### 8.1 Прямая параметризация обычно не работает

Наивный подход — «сделаем свободными все числа из условия и отсеем плохие
наборы» — даёт доли процента годных вариантов, потому что условия целочисленности
перемножаются. Проверено на задаче про путь: 0,03 %.

### 8.2 Обратная параметризация

Свободными делают те величины, через которые остальные выражаются **точно**,
а «красивые» числа из условия выводят.

Пример (задача про путь по частям): вместо того чтобы сэмплировать обе скорости
и полное время, свободны `v1`, разрыв скоростей `delta`, время верхом и длина
хвоста, а время бега выводится из тождества

```
run_min · delta = 3·tail_m/50 + v1·ride_min
```

Доля годных наборов выросла с 0,03 % до 6 %.

### 8.3 Работа в целых единицах

Считай в **метрах и минутах**, а не в километрах и часах: тогда все промежуточные
величины целые, а `Fraction`/`float` появляются только в ответе. Переход
км/ч × мин → м: `v * t * 50 / 3`.

### 8.4 Порог

Доля удачных попыток из отчёта валидации — **не ниже 5 %**. Ниже — переделывать
параметризацию. Лимит попыток (300) не трогать.

### 8.5 Структурные ограничения важнее вкусовых

Прежде чем «улучшать» задачу, проверь, не следует ли странность из математики.
В исходной задаче про хоббита «шёл 6 км/ч, потом бежал 5 км/ч» выглядит опечаткой,
но из условия «время на последний участок положительно» при делении пути пополам
строго следует `v2 < v1`. Значит, менять надо не числа, а **текст**: второй участок
описан как «устал и пошёл медленнее». Бег быстрее ходьбы становится возможен только
при другой доле пути — это отдельный, более сложный шаблон.

## 9. Чек-лист `constraints`

Для каждого шаблона пройди список и добавь то, что применимо:

- [ ] **Точность деления:** для каждого `//` есть `% == 0`.
- [ ] **Положительность:** все времена, расстояния, количества, остатки > 0.
- [ ] **Согласованность с сюжетом:** «сдача положительна», «осталось меньше, чем было»,
      «встреча происходит до конца пути».
- [ ] **Самопроверка:** восстанови по вычисленным величинам одну из исходных
      и сравни с ней. Пример: `run_m * 3 == v2 * run_min * 50`. Это ловит опечатку
      в формуле лучше любого теста.
- [ ] **Физическая осмысленность:** скорости в разумных пределах, транспорт не медленнее
      пешехода, возраст неотрицателен, число людей целое.
- [ ] **Красота чисел:** путь кратен 500 м, время кратно 5 минутам, ответ не «7,3333».
- [ ] **Невырожденность:** параметры не совпадают там, где это убивает задачу
      (`a != b`, `delta >= 1`).

Каждый предикат обязан возвращать `True`/`False`. Предикат, который **никогда**
не выполняется, обнаружится сразу: генерация упадёт с явной ошибкой.

## 10. Чек-лист текста (читать глазами 10 примеров)

- [ ] Каждое упоминание персонажа — в правильном падеже (слот, а не голое имя).
- [ ] Каждый глагол прошедшего времени рядом с персонажем — через `{:g,…}`.
      Проверь на женском персонаже: «Нюша шла», «Совунья устала».
- [ ] Числа с существительными согласованы: 1 час / 2 часа / 5 часов / 2,5 часа.
- [ ] Персонажи из одной вселенной, роли не дублируются.
- [ ] Предметы уместны для вселенной.
- [ ] Условие однозначно: из текста понятно, что именно спрашивается.
      («Прошёл пешком» — это только шагом или шагом и бегом? Если неоднозначно —
      переформулируй.)
- [ ] Ответ не подсказан в условии, слова «Ответ:» нет.
- [ ] Нет двойных пробелов, текст заканчивается знаком препинания.
- [ ] Задача решается устно за 3 минуты или требует ровно того уровня, который задуман.

## 11. Тест с независимым решателем

Единственный Python, который пишет агент. Правило: решатель обязан **решать задачу
по её условию**, а не повторять формулы шаблона. Если в шаблоне `S = 2*(d2+c)`,
тест должен прийти к `S` иначе — например, решив уравнение относительно `S`.

```python
def test_matches_independent_solution(self):
    for seed in range(25):
        generated = generate_active_template(TEMPLATE, random.Random(seed))
        values = generated["parameters"]
        v1, v2 = Fraction(values["v1"]), Fraction(values["v2"])
        total_h = Fraction(values["total_min"], 60)
        # ... решение задачи с нуля, в Fraction, без обращения к derived_values
        self.assertEqual(generated["answer"], [expected_a, expected_b], f"seed {seed}")
```

Считай в `Fraction`, а не во `float`: сравнение дробей должно быть точным.
Минимум 25 сидов. Плюс проверки: текст без `{`, без двойных пробелов, начинается
с заглавной, заканчивается знаком препинания.

## 12. Когда задачу отклонять

Записывай в журнал с одной из причин:

| Причина | Когда |
|---------|-------|
| `non_parametric` | у задачи нет свободных чисел: меняя их, получаем другую задачу или бессмыслицу (криптарифмы с уникальным решением, «докажите, что…») |
| `search_answer` | ответ требует перебора или поиска, а не формулы (`solver_strategy: formula` не подходит) |
| `structured_answer` | ответ — конструкция, перечисление всех вариантов, чертёж |
| `duplicate` | параметрический близнец уже перенесённой задачи; указать `template_id` |
| `corrupt_source` | текст в корпусе побит OCR и восстановить условие нельзя |
| `needs_new_slot` | нужна морфология, которой пока нет (склонение прилагательных, согласование в мн. ч. по роду) — с описанием, чего именно не хватает |

Отклонение — нормальный результат. Плохой результат — шаблон, который выдаёт
кривой русский или неверный ответ.

## 14. Известные ловушки

Собраны на первом срезе, каждая стоила времени:

1. `{apple:count,n}` — существительное первым, число вторым. Наоборот не работает.
2. Между числом и словом движок ставит **неразрывный пробел** (` `).
   В тестах сравнивай с ним, а не с обычным пробелом.
3. `//` скрывает нецелость — всегда парой с `% == 0`.
4. Деление на ноль внутри `derived_values` считается **дефектом шаблона**:
   пересэмплирование его не спрячет, валидация упадёт. Ставь constraint на делитель.
5. Неиспользуемый параметр — ошибка валидации. Если параметр нужен только для
   ограничения, он всё равно должен появиться в тексте или в выражениях.
6. Слово `Ответ:` в тексте условия запрещено проверкой.
7. Буквенные маркеры пунктов (`а)`, `б)`) движок делает заглавными после точки —
   используй `1)`, `2)`.
8. Персонаж со строчной буквы («кот Матроскин») в середине предложения должен
   оставаться строчным — не подставляй заглавную вручную.
9. Не забывай `constraints` в JSON: без них сайт сгенерирует набор, который
   ты считал недопустимым.
10. Если единица измерения ответа зависит от случайно выбранного слова
    («олимпиада» vs «викторина»), используй `unit_param`, а не `unit` —
    иначе ответ будет согласован с чужим словом («Сколько викторин... Ответ: 20
    олимпиад»).
11. `{place:loc}` — где, `{place:dir}` — куда. «Отправился в Хижине чудес»
    проходит все автоматические проверки и ловится только глазами.
12. Не пиши предлог «с» руками перед творительным: используй `{hero:with}`,
    иначе получится «с Свеном» вместо «со Свеном».
13. Одно и то же имя может быть в разных мирах («Ёжик» — Смешарики и «Ёжик
    в тумане»; «Осёл» — Шрек и бременские музыканты). Не строй отображение
    имя → вселенная: сравнивай `character.universe` у самого объекта.
14. Целочисленные суммы дробей (например, сумма двух темпов работы) считай
    через `//` и `%` над целыми числами, а не через `/`: обычное деление даёт
    `float`, и на подобных числах вроде 34/6+13/3 накапливается ошибка
    округления, которая ломает проверку «сумма целая».

## 16. Пример: разбор задачи №8 целиком

**Исходный текст:**

> Хоббит первую половину пути шел со скоростью 6 км/ч, еще половину времени бежал
> со скоростью 5 км/ч. А оставшиеся 500 метров его довез Гендальф.
> a) Какой путь Хоббит прошел пешком? b) Сколько времени Хоббит ехал на лошади?
> Если весь путь занял 3 часа?

**Шаг 2–4. Математика.** Обозначим путь `S`, полное время `T`.

```
d1 = S/2,  t1 = S/(2·v1)
t2 = T/2,  d2 = v2·T/2
d3 = tail, t3 = T - t1 - t2
d1 + d2 + d3 = S   →   S = 2·(v2·T/2 + tail)
```

Проверка осмысленности: `t3 > 0` даёт `v2 < v1 - 2·tail/T`. Второй участок
**всегда** медленнее первого — правим не числа, а формулировку. И `tail/t3` при
исходных числах равно 3 км/ч: лошадь медленнее пешехода — добавляем
constraint `ride_kmh > v1`.

**Шаг 5. Доля годных наборов** при прямой параметризации — 0,03 %. Переходим
к обратной: свободны `v1`, `delta`, `ride_min`, `tail_m`; `run_min` выводится.
Стало 6 %.

**Шаг 7. Текст:**

```
{hero:nom} {hero:g,шёл|шла} первую половину пути со скоростью {v1} км/ч,
а потом {hero:g,устал|устала} и ровно половину всего времени {hero:g,шёл|шла}
медленнее — со скоростью {v2} км/ч. Последние {metre:count,tail_m} {hero:acc}
{rider:g,подвёз|подвезла} {rider:nom}. Вся дорога заняла {hour:count,total_h}.
1) Какой путь {hero:nom} {hero:g,прошёл|прошла} пешком?
2) Сколько времени {hero:nom} {hero:g,ехал|ехала} с {rider:ins}?
```

**Результат:**

```
Почтальон Печкин шёл первую половину пути со скоростью 6 км/ч, а потом устал
и ровно половину всего времени шёл медленнее — со скоростью 4 км/ч. Последние
1500 метров почтальона Печкина подвёз галчонок Хватайка. Вся дорога заняла
2,5 часа. 1) Какой путь почтальон Печкин прошёл пешком? 2) Сколько времени
почтальон Печкин ехал с галчонком Хватайкой?
Ответ: 1) 11,5 километра; 2) 10 минут
```

Готовый JSON — `data/template_studio/library/motion_half_path_half_time_ride.json`,
усложнённый вариант той же задачи (треть пути, бег быстрее ходьбы, два неизвестных) —
`motion_third_path_third_time_ride.json`. Оба читать перед началом работы: это
эталон оформления, включая `math_notes`.
