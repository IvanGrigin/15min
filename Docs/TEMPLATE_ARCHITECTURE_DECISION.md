# Решение об архитектуре шаблонов

Принято 25.07.2026, реализовано. Здесь — короткая запись «что выбрали и почему»,
чтобы следующий агент не пересматривал решение заново и не изобретал пятый путь.

## Решение

**Одна задача — одна JSON-запись.** Текст условия со слотами падежей, параметры,
ограничения и формула ответа лежат в `data/template_studio/library/*.json`.
Python задачу решает и проверяет, но не формулирует.

Морфология — первоклассная операция шаблона, а не забота автора текста:
падеж, род, предлог и согласование с числительным берутся из данных.

## Что рассматривали

На момент решения в репозитории сосуществовали четыре подхода:

| | Подход | Текст задачи | Падежи | Цена нового шаблона |
|---|---|---|---|---|
| A | 33 Python-генератора | f-строки в коде | нет | функция + JSON + правка manifest + ветка в сайте + тест |
| B | архив из PDF, 1088 записей | шаблон только с числовыми слотами | нет | новый PDF |
| C | Template Studio | JSON + `str.format` | нет | один JSON |
| D | движок `problemgen/russian` | слоты `{key:падеж}` | да | нет обвязки: ни хранения, ни ответов, ни валидации |

A и B закрыты, подробности — `Docs/ARCHIVED_LEGACY.md`.

Выбрана связка **C + D**: у C уже были декларативное хранение, безопасный
вычислитель ответа и валидация с независимым пересчётом на десяти сидах;
у D — честная морфология с явными формами. Не хватало ровно стыка между ними.

## Что для этого понадобилось в движке

Список закрыт, все пункты сделаны:

- слоты `{hero:gen}`, `{item:count,n}`, `{hero:g,купил|купила}`,
  `{place:loc}` / `{place:dir}`, `{hero:with}`;
- типы параметров `character`, `noun`, `location`; предметы из вселенной;
- `constraints` с отсевом наборов (раньше поле молча терялось при активации);
- сравнения и тернарник в безопасном вычислителе;
- согласование единиц в ответе, в том числе через `unit_param`;
- реестры: 268 персонажей, 42 вселенные, 84 локации, 258 существительных.

## Принципы, которые нельзя нарушать

1. **Никакого автосклонения в рантайме.** Все формы задаются явно в данных.
   Правила склонения (`scripts/declension_rules.py`) — инструмент подготовки
   данных: они дают заготовку, человек её подтверждает.
2. **Никакой LLM в момент выдачи задачи.** Генерация детерминирована
   и воспроизводима по seed.
3. **Новая задача не стоит ни строки Python.** Единственный допустимый Python —
   тест с независимым решателем.
4. **Валидатор — не мерило качества задачи.** Он проверяет самосогласованность:
   шаблон может пройти все десять проверок и остаться непригодным. Десять
   примеров читаются глазами — это обязательный шаг, а не формальность.

## Что измерено и отклонено

**Локальная модель как автор шаблонов** — 0 годных из 10, три прогона подряд.
Ошибки не в математике, а в смысле: формула сворачивалась в тождественную
единицу, `answer_expression` расходился с собственными `math_notes`.

**Локальная модель как источник словоформ** — хуже простых правил: путает
творительный падеж с винительным, предложный с дательным.

Цифры и методика — `Docs/DATA_PIPELINE.md`. Код обоих замеров лежит в ветке
`archive/legacy-python-generators`; если появится заметно более сильная модель,
замер стоит повторить, но начинать надо с замера, а не с внедрения.
